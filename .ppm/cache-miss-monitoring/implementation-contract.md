# Cache monitor implementation contract

Last updated: 2026-11-13. Governs unfinished phase_1 work and supersedes conflicting historic gates in plan/schema/evidence. Frozen phase_0 artifacts remain historical. Approved: continue phase_1 with installed SDK 1.5.0; IDs local only; fingerprints of observed objects, not wire bytes; retry identity unknown unless explicitly local.

## Persisted JSONL record

Exact top-level keys (no extras): `schema_version:1`; `local_epoch_id`, `local_invocation_id`, `local_stream_id` lowercase UUIDv4 strings; `sequence` nonnegative safe integer monotonic within epoch; `invocation_index` nonnegative safe integer monotonic within stream, ordering only; `timestamp_ms` nonnegative safe integer; `provider` enum `openai|anthropic|google|other`; `model_id_hash`, `config_id_hash` nullable lowercase 64-hex HMAC; `event_type` enum `request|response|unknown`; `association` enum `paired|unmatched|retry_ambiguous|telemetry_gap|context_reset|incomplete_fingerprint`; `event_type:"request"`/`"response"` with live handle use `paired`; unknown records use their explicit reason. `paired` marks events carrying a live local handle; analyzer declares pair only when exactly one request event and one successful response event share the handle tuple. Missing response is always `unmatched_response` regardless of request association. `fingerprints` exactly `{prompt: Fingerprint|null}`; `Fingerprint={hmac_sha256:lowercase-64-hex,bytes:integer 0..131072,complete:boolean}`; `usage` null or exact `{input_tokens,output_tokens,cache_read_tokens,cache_write_tokens}`, each null or integer 0..2147483647; `incomplete:boolean`. Response and unknown records always have `fingerprints.prompt:null`. Request records carry observed effective prompt payload fingerprint or null/incomplete. Missing usage is null, never zero. Persist no payload, headers, paths, raw identifiers, raw model/config strings, or unrecognized fields.

Report labels, exact fixed set: `observed_client_payload_delta`, `unchanged_observed_payload_low_cache_upstream_or_unobserved`, `insufficient_evidence`, `telemetry_gap`, `context_reset`, `unmatched_response`, `retry_ambiguous`, `incomplete_fingerprint`, `uncorrelated_payload_only`. “Low cache” label allowed only when response has observed `cache_read_tokens===0` and `input_tokens>0`; otherwise stable prompt emits `insufficient_evidence` or `observed_client_payload_delta`; never assert provider cause.

## Exact recorder API and local identities

```ts
type ProviderEnum = 'openai'|'anthropic'|'google'|'other';
type Usage = { input_tokens:number|null; output_tokens:number|null; cache_read_tokens:number|null; cache_write_tokens:number|null };
type InvocationHandle = Readonly<{ localEpochId:string; localInvocationId:string; localStreamId:string; invocationIndex:number; provider:ProviderEnum; modelId:string|null; configId:string|null }>;
interface CacheMonitor {
 readonly localEpochId:string|null;
 beginInvocation(input:{localStreamId:string; invocationIndex:number; provider:ProviderEnum; modelId?:string|null; configId?:string|null}):InvocationHandle|null;
 recordRequest(handle:InvocationHandle,input:{payload:unknown}):void;
 recordResponse(handle:InvocationHandle,input:{usage?:Usage|null}):void;
 markUnknown(handle:InvocationHandle|null,reason:'unmatched'|'retry_ambiguous'|'telemetry_gap'|'context_reset'|'incomplete_fingerprint'):void;
 close(input?:{drain?:boolean}):Promise<void>;
}
createCacheMonitor(options:{enabled:boolean;directory:string;now?:()=>number;randomUUID?:()=>string}):CacheMonitor
```

When enabled, recorder creates random 32-byte memory-only epoch HMAC key and random UUIDv4 `localEpochId`; wrapper creates random UUIDv4 `localStreamId` per session; `beginInvocation` creates UUIDv4 local invocation ID and bounded pending handle. All are explicitly Pi Web local IDs, never SDK/provider IDs. Disabled/fail-open returns null and performs no capture/key/directory creation. Handle is unique tuple `(localEpochId,localInvocationId,localStreamId)`. `recordRequest` and `recordResponse` write events with this same tuple and `association:"paired"`; analyzer establishes pair only when it finds exactly one request and one response event. `recordResponse` associates only by exact handle tuple, never by time/order. `markUnknown(null,reason)` writes unknown record with all-zero UUID sentinel for missing local IDs; sentinel is reserved and never accepted as generated ID. Unmatched response uses `event_type:"unknown"`, `association:"unmatched"`, null fingerprint/usage. After request fingerprinting, response/unknown, or close, release pending handle and any payload reference; pending map maximum 64. `recordRequest` does not release handle because response pairing remains pending. No payload retained after synchronous fingerprinting.

## HMAC, serialization, and bounds

HMAC domains are fixed ASCII tags `pi-web-cache-monitor:v1:prompt`, `...:model`, `...:config`; input framing is 4-byte unsigned big-endian tag length, tag bytes, 4-byte unsigned big-endian data length, data bytes. Prompt uses full canonical UTF-8 bytes; model/config use UTF-8 string values; no unkeyed hash and no raw strings persisted. Fingerprint values are epoch-keyed and comparable only within same epoch.

Prompt serializer accepts only null/boolean/finite number/string/array/plain object with own enumerable data properties. Reject accessors/getters, symbols, cycles, non-plain prototypes, unsafe keys `__proto__`, `constructor`, `prototype`, unsupported values. Sort keys lexicographically; compact JSON encoding via `JSON.stringify`. Depth <=32, nodes <=10,000, UTF-8 string <=64 KiB, canonical bytes <=128 KiB per request payload. No combined prompt/result cap: response content is never fingerprinted. Oversize, invalid, or serialization exception yields null fingerprint, `incomplete:true`, `association:"incomplete_fingerprint"`, and never hashes a truncated prefix. HMAC model/config only when provided; absent value null. HMAC key lifetime is epoch; rotate on restart/reset.

Usage: recordResponse accepts only supplied usage object with exactly four known fields; absent fields become null; invalid type/key/range makes entire usage null and `incomplete:true`; never infer usage. Any serialized record >16 KiB including newline is dropped; increment gap counter and tag next emitted record `association:"telemetry_gap"`, `incomplete:true`. If dropped event is a request/response, also emit bounded unknown event if it fits; otherwise retain gap counter only. Queue overflow follows same gap behavior. If an error occurs after handle allocation, mark it unknown and release handle. Keep existing caps: queue <=64 records and <=1 MiB; record <=16 KiB; JSONL file <=1 MiB; 3 rotated files; retention 7 days from oldest record timestamp; 32 chunks/category ×4 KiB and total 128 KiB/event where applicable (whole prompt cap above is tighter); directories/files 0700/0600. Overflow and I/O errors drop telemetry only. No raw content persisted.

## Analyzer semantics

CLI `node scripts/analyze-cache-monitor.mjs <capture-dir>`; caps 16 files, 1 MiB/file, 4 MiB total, 16 KiB/line, 2 MiB report; invalid/oversized input exits nonzero with no partial report. Validate exact schema and enums. Group by `(local_epoch_id,local_stream_id,provider,model_id_hash,config_id_hash)`; require non-null model/config HMAC to compare; never combine groups/epochs. Deduplicate byte-identical record key `(epoch,invocation,stream,event_type,sequence)`; conflicting duplicates => `telemetry_gap` for invocation. Exactly one request and one response per invocation tuple are required; multiple request or response events => `retry_ambiguous` and suppress comparison. Sequence gaps => gap. Pair request with response only by exact local invocation tuple; missing response => `unmatched_response`; multiple request/onPayload observations for same handle => `retry_ambiguous`, suppress comparison. `invocation_index` only sorts candidate invocations; compare request fingerprints across adjacent indices only, never use index to pair response. Both invocations need one request and one response, unique contiguous indices, same group/epoch/stream, complete non-null request fingerprints, no gaps/unknown states. Otherwise emit `incomplete_fingerprint`, `insufficient_evidence`, or matching explicit label. Stable result may use `unchanged_observed_payload_low_cache_upstream_or_unobserved` only with exact observed zero cache_read and positive input_tokens; absent usage produces `insufficient_evidence`. Output fixed labels/counts/metadata only.

## Installed SDK integration: verified per-session method

Installed SDK 1.5.0 evidence: `dist/core/sdk.js` line 75 reads `options.modelRuntime`; line 271 invokes captured `modelRuntime.streamSimple(model,context,requestOptions)`. `dist/core/agent-session-services.js` line 133 passes `options.services.modelRuntime` into session creation. `streamSimple` is the only method wrapper target; do not wrap `stream`, Agent stream function, or other runtime method. In `lib/rpc-manager.ts` at `createAgentSessionFromServices` call (around line 3823), make a shallow copy of services and a per-session `Proxy` around its existing modelRuntime, then pass copied services to SDK. Proxy `get(target,key)` returns a wrapper only for `streamSimple`; for every other property use `Reflect.get(target,key,target)`, and bind function values to target so private fields work. Wrapped `streamSimple` calls original via `Reflect.apply(original,target,args)` and returns exact original stream object. This is per-session proxy only; never mutate shared runtime/prototype.

At `streamSimple` call, create local invocation handle before calling original; prompt context is not final provider payload and is not fingerprinted. Clone only the options object and wrap existing `onPayload` (or install pass-through if absent), preserving all other options. Call original callback exactly once with original arguments; await result; if result is `undefined`, effective payload is original payload, otherwise effective payload is returned replacement. Invoke `recordRequest(handle,{payload:effectivePayload})` after success; return exact callback result unchanged. If callback rejects, propagate same rejection and do not observe. Catch all recorder/observer errors without changing callback result/error. Count onPayload calls per handle; >1 marks `retry_ambiguous`, does not create request-response pairing and suppresses prompt comparison. Attach to original stream `void originalStream.result().then(onSuccess,onFailure)` solely for observation: fulfillment first checks the final assistant `stopReason`: `error` or `aborted` calls `markUnknown(handle,'unmatched')`; only `stop`, `length`, or `toolUse` with exactly one successful payload observation calls `recordResponse(handle,{usage:extractUsage(result)})`. Zero observations calls `markUnknown(handle,'telemetry_gap')`; multiple observations calls `markUnknown(handle,'retry_ambiguous')`. Promise rejection calls `markUnknown(handle,'unmatched')`;  both observers catch/swallow errors. `extractUsage` reads only plain `result.usage` SDK fields `input`, `output`, `cacheRead`, `cacheWrite`, mapping them to `input_tokens`, `output_tokens`, `cache_read_tokens`, `cache_write_tokens`; SDK aggregate/cost fields are ignored, never persisted. Each absent or invalid counter becomes null. It never reads assistant content. Return original stream immediately, unchanged; never consume iterator, replace result, return a derived stream, or alter resolution/rejection. Release handle when response/unknown recorded. Each `streamSimple` call gets distinct local invocation; retry relation is unknown. Increment `invocationIndex` once per call, even if stream creation throws; on synchronous throw, call `markUnknown(handle,'unmatched')`, then rethrow the exact error. A stable per-session stream ID and monotonic invocation index are maintained only by this wrapper.

## Source proof and retention clarification

SDK `sdk.js:193-213` builds request options with `...options`; `pi-agent-core/dist/agent-loop.js:276-281` includes `onPayload` in those options. Thus `sdk.js:271` forwards the invocation callback into `streamSimple`. Provider adapters await that callback within the same invocation that owns the returned stream. This proves local invocation association only, never hidden attempt identity. `pi-ai/dist/utils/event-stream.js:92-100` resolves both done and error events, so inspect `stopReason` as specified above, not Promise rejection alone. Unsupported provider paths or missing callbacks remain unknown. Existing callback replacement is observed only after callback success.

For phase_1, whole-object HMAC framing and local identities here explicitly supersede historic chunk tags, byte-observation requirements, and SDK-only IDs in plan.md/schema.md. Retention requirements remain unchanged: seven days from each file's oldest record timestamp, never filesystem clocks. Enabled startup validates bounded regular capture files and deletes expired captures before writes; reject future timestamps/malformed files, drop diagnostics if cleanup fails. Before each append/rotation recheck expiry. Schedule idle cleanup at oldest-file expiry, plus bounded periodic rechecks for clock changes; timers unref and cleared on close. At deadline delete, never merely rename; rotation never extends retention. Stop/disabled/suspended process cannot guarantee real-time deletion; next enabled startup/resume checks before writes. Analyzer is read-only, rejects expired/future/non-regular input with generic errors and no partial output. Dedicated capture directory only, never scan/delete arbitrary directories.
