## Constraints and invariants

- Approved override: SDK gate cleared by user; local invocation/epoch/stream IDs are Pi Web local identifiers, not SDK IDs. No retry identity assumed; ambiguous retry stays unknown. Deterministic observed-object fingerprints are not wire bytes. Full API and strict privacy contract in `implementation-contract.md`.
- Env `PI_WEB_CACHE_MONITOR=1`; otherwise no capture, directory creation, or key creation.
- Retain existing strict event allowlist, numeric validation, HMAC and privacy constraints. Captured object fingerprint limits and unsupported values are defined in `implementation-contract.md`; no arbitrary raw content persists.
- HMAC: fresh random 32-byte key per capture epoch, memory only, never persisted/logged; epoch change on restart/reset. Current whole-object framing is uint32BE tag length, ASCII domain tag, uint32BE canonical UTF-8 data length, data. Domains are `pi-web-cache-monitor:v1:prompt`, `pi-web-cache-monitor:v1:model`, `pi-web-cache-monitor:v1:config`. No unkeyed hashes. Historical chunk framing in frozen `schema.md` is superseded by approved `implementation-contract.md`.
- Retention: seven days from oldest record's `timestamp_ms` in each capture file, never filesystem creation/modification time. Rotate or delete entire file before its oldest record expires; startup removes expired captures before accepting writes. No cleanup while stopped or disabled; remove expired captures on next enabled startup and disclose manual deletion for immediate removal. Analyzer remains read-only and refuses expired input.
- Bounds: async queue max 64 records and 1 MiB; record max 16 KiB; JSONL file max 1 MiB; 3 rotated files; retention 7 days; max 32 chunks/category × 4 KiB, total fingerprint input 128 KiB/event. Overflow drops affected records/chunks and sets `incomplete=true`; never claim full equality/change. Byte chunks are not tokens or token-prefix evidence. Directory/file mode 0700/0600; permissions, rotation, retention, serialization, and disk errors drop diagnostics only. No endpoint, headers, paths, prompt text, tool payloads, or raw custom IDs persisted. Document user-directed capture-directory deletion and seven-day retention in `schema.md`.
- Shared recorder signatures: `createCacheMonitor(options)`, `beginInvocation(input)`, `recordRequest(handle,{payload})`, `recordResponse(handle,{usage})`, `markUnknown(handle|null,reason)`, `close({drain})`. API and exact event schema follow approved `implementation-contract.md`; raw payload is synchronously fingerprinted, never retained or persisted. `close({drain:true})` waits for queued writes; false discards pending; close idempotent; no writes after close. Observer preserves exact callback input/output and failures never affect requests.
- Compare observed object fingerprints only within same local epoch and stream identity. Local IDs are not SDK/provider IDs. Retries remain unknown unless exact local invocation association exists; no causal claims. See `implementation-contract.md`.
- CLI exact invocation: `node scripts/analyze-cache-monitor.mjs <capture-dir>`. Retain maximum 16 files, 1 MiB/file, 4 MiB total, 16 KiB/line, 2 MiB report. Invalid/oversized input exits nonzero without partial report. Compare only same-epoch/same-stream local object fingerprints; no retry inference or provider-internal cause claims.
- Verification uses isolated temporary directories and fake callbacks/providers only; no DB, live service, migration, network, paid provider call, build, or restart. No migrations, seed data, or schema changes required. Installed SDK 1.5.0 alignment and operator gate are already cleared; no synchronization is required or authorized.
- Do not run `next build`, paid calls, service restart, dependency changes, or network actions. Do not alter ESLint config. Full `npm run lint` previously timed out traversing existing `.next-old-20261026-130819` generated chunks; use installed `node_modules/.bin/eslint`, not `npx`.
