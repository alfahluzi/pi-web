# System Prompt Markdown Panel

Created: 2026-11-02
Last updated: 2026-11-02

## 1. Objective

Replace the `pre-wrap` monospace dump in the top bar's **System** panel (`components/SystemPromptPanel.tsx`) with a designed panel: a header row (title, Copy, Expand/collapse) plus markdown-rendered prose where each pi wrapper tag (`<tools>`, `<rules>`, `<project_context>`, …) becomes a labelled section heading with a hairline rule. The prompt's Markdown must actually render (bullets, numbered lists, inline code, headings) instead of being flattened, and the wrapper tags must never leak into the output as broken HTML or silently vanish.

## 3. Current-state findings

Verified in this repository by reading the code and by probed renders through this repo's own `react-markdown@10` + `rehype-raw` + `rehype-sanitize` (`markdownRemarkPlugins` + `markdownRehypePlugins`), not assumed:

1. The prompt is emitted by pi as a plain preamble plus `` `<${name}>\n${content}\n</${name}>` `` sections, lower-case names with underscores. The standard sections, in live document order, are: **preamble**, `tools`, `rules`, `docs`, `addendum`, `project_context`, `project_instructions`, `skills`, `available_skills`, `skill` (repeated, 8 times in this checkout), `cwd`, `mcp_servers`. Some carry attributes (`<project_instructions path="…">`) and nest.
2. Wrapper tags with **no** underscore are valid HTML tag names, so with `rehypeRaw` a line holding `<tools>` alone starts a CommonMark *HTML block*: `<tools>\n- a\n- b\n</tools>` renders as `"\n- a\n- b\n"` — the paired close tag is consumed by the HTML block and only the bullet lines survive, as literal text, no longer a list. This is the visible bug today (`pre-wrap` masks it).
3. Tags **with** an underscore (`<project_context>`, `available_skills`) are *not* valid HTML tag names, so they render as literal escaped text — a different bug (noise), which the segmenter also removes.
4. A lone **inline** tag-like token outside code is dropped by the sanitizer with no trace: `Pass --tools, -t <tools>, or edit` renders as `Pass --tools, -t , or edit`. Paired inline tags keep their children (`<name>x</name>` → `x`). `a Vec<T>` renders as `a Vec`. Backslash-escaping makes the token visible again (`\<tools\>` → `&lt;tools&gt;`, `Vec\<T>` → `Vec&lt;T&gt;`), and the escape survives in headings, list items and table cells (probed).
5. `defaultSchema.tagNames` is therefore the exact predicate for "would the sanitizer eat this tag"; `b`, `br`, `code`, `kbd`, `details` are allowed, `tools`, `name`, `skill`, `location`, `cwd`, `T` are not.
6. Indented wrapper bodies must be dedented: the live skills block indents `<skill>` by 2 spaces and its `<name>`/`<description>`/`<location>` children by 4, which Markdown turns into a code block (probed) — a naive segmenter renders the skills list as a `<pre>` full of visible backslashes.
7. **Frontmatter is silently deleted.** Because `markdownRemarkPlugins` starts with `[remarkFrontmatter, ["yaml"]]`, a body of `---\ntitle: Repo rules\ntags: a, b\n---\n\n# Heading\n\ntext` renders as `"<h1>Heading</h1>\n<p>text</p>"` — the whole fenced block is gone. A `...`-closed block is *not* frontmatter (renders as `<hr/>` + text), and a CRLF body *is* frontmatter (also deleted). Escaping both `---` fence lines renders `"<p>---\ntitle: Repo rules\ntags: a, b\n---</p>"` — content preserved, no bogus heading (escaping only the opening fence instead produces an `<h2>`, probed).
8. **HTML comments are deleted**: `<!-- hidden -->\nhello` renders as `"\n<p>hello</p>"`.
9. `keepLineBreaks` inserts a `<br/>` per line: `name: frontend-design\ndescription: Build polished UI` → `<p>name: frontend-design<br/>description: Build polished UI</p>`; hard-wrapped prose (`this line is a sentence\nand this is another line`) collapses to one paragraph without it.

## 5. Proposed approach

### 5.1 `lib/system-prompt-markdown.ts` — pure segmenter (new)

No `"use client"`, no React, no Node built-ins. Exports exactly:

```ts
export type SystemPromptSegment =
  | { kind: "prose"; depth: number; markdown: string; lineOriented: boolean }
  | { kind: "section"; depth: number; name: string; label: string; attributes: string };
export function parseSystemPrompt(prompt: string): SystemPromptSegment[];
export function escapeStrayTags(markdown: string): string;
```

**5.1.1 `depth` — stated once, and only this meaning.** A `section` segment carries the depth at which its **label** renders: the number of wrapper sections already open when the label is emitted, i.e. its parent's depth (top-level = `0`). The prose segments of that section's body carry `depth + 1`, because one more section is open while they are emitted. **Prose flushed while the stack is empty — the preamble before the first section — is depth `0`**, so it gets no indent and no left border (the component keys both on `depth > 0`); asserted in test (a). Therefore, in this checkout, `skills` is depth 0, `available_skills` depth 1, `skill` depth 2, and the `<name>`/`<description>`/`<location>` body of a `skill` is prose at depth 3. Depth is not capped by the module; the component clamps only the visual indent (see §5.2).

**5.1.2 Structural lines — one predicate, not two opinions.** A line is structural only when **both** hold:

1. it matches `/^ {0,3}<(\/?)([a-z][a-z0-9_-]*)((?:\s[^<>]*?)?)\s*(\/?)>\s*$/` — leading whitespace capped at 3 spaces (4 spaces is a Markdown code block, in which case the line is ordinary prose), and the name restricted to `[a-z][a-z0-9_-]*`, pi's own naming rule (this also keeps `Vec<T>`-style and `<T>`-style tokens out);
2. the name is **not** in `safeTags`, the sanitizer's own allow-list, built once at module scope as `const safeTags = new Set(defaultSchema.tagNames ?? []);` and shared with `escapeStrayTags` (§5.1.7).

*Why this predicate (answer to the auditor's first question).* A tag-only line whose tag the pipeline can render (`br`, `div`, `details`, `summary`, `p`, `a`, `img`, `li`, `span`, `input` — all in the 53-name allow-list, §3.16) is **prose**: project docs legitimately contain `<br>`, `<details>/<summary>` and `<div align="center">`. Treating it as a section opener invented a bogus label *and*, because a close only pops on exact stack-top equality, made the enclosing section's real close tag fail to match and leak as escaped text with every later section one level deeper (audited on `</project_context>` / `</cwd>`). One predicate over the same set the escaper uses fixes both halves, with no balanced-tag lookahead, no wrapper allow-list, no backslash bookkeeping and nothing that needs to look at escaped text: the predicate runs at scan time, i.e. **before `neutralizeFrontmatter` and before `escapeStrayTags` run in the flush (§5.1.4)**, so no rule depends on another rule's output. Cost is one `Set.has` per tag-shaped line. None of pi's twelve canonical names is in `safeTags` (§3.16), and test (m) asserts all twelve still become sections, so a future collision fails loudly instead of silently turning a real section into prose.

Given that predicate: group 1 `/` marks a close tag, group 2 the name, group 3 the attribute text, group 4 `/` a self-closing tag. Open (not self-closing) → flush the buffer as prose at the current depth, push the `section` segment, push the name on the stack. Close → only when the stack is non-empty **and** its top equals the name: flush, then pop; otherwise it is not structural and stays in the buffer as text (the escaper then makes it visible). Self-closing tag line → ordinary prose. `label = name.replace(/_/g, " ")` (CSS uppercases; never uppercase here, CJK names must survive). `attributes` = group 3 trimmed, or `""`.

**5.1.3 Fences first.** A fence opens on `/^ {0,3}(`{3,}|~{3,})/` and closes on a later line with the same marker character and length ≥ the opener. Inside a fence nothing is structural in either direction (a fence opened in a section body may contain `</tools>`), and `escapeStrayTags` skips fenced lines with the same rule.

**5.1.4 Flushing a buffer.** Drop leading/trailing blank lines → dedent by the smallest leading-whitespace count of the non-blank lines (required: the live skills block indents by 4 spaces) → trim trailing whitespace per line → skip if only whitespace → compute `lineOriented` (§5.1.6) → `neutralizeFrontmatter` (§5.1.5) → `escapeStrayTags` → join with `"\n"`. End of input flushes at the current depth; `parseSystemPrompt("")` is `[]`.

**5.1.5 Leading frontmatter is neutralised (not deleted).** `markdownRemarkPlugins` begins with `remarkFrontmatter`, so a body starting with a `---` … `---` fence loses that whole block (§3.7). `neutralizeFrontmatter(markdown)`: when the first line is exactly `---` and a later line is exactly `---`, prefix `\` to those two lines. Probed result: `<p>---\ntitle: Repo rules\n---</p>` — metadata visible as text, no bogus heading, nothing dropped. Only the block-start position is touched, so a `---` horizontal rule elsewhere in an `AGENTS.md` body is left alone. HTML comments are **not** neutralised: they stay dropped, documented in §7 and pinned by a test (§8).

**5.1.6 `lineOriented` — content shape, never depth.** `lineOriented` is `true` iff the dedented body has **no blank (whitespace-only) line** and **every non-blank line** matches either `KEYED = /^\s*[\w.$-]+\s*:(\s|$)/` (a `key: value` shape) or `TAGISH = /^\s*\\?<\/?[A-Za-z][A-Za-z0-9_-]*(?=[\s/>]|$)/` (a line opening with a tag-ish/label token). It is computed on the dedented body before neutralising and escaping, so the predicate never depends on other rules. Rationale: the 46 KB `AGENTS.md` body of `project_instructions` sits at prose depth 2, and a depth-based rule put a `<br/>` after every hard-wrapped line of it. Hard-wrapped prose is `false`; a `<skill>` body (`name: …` / `description: …` / `location: …`) is `true`; an empty-block-free body of only `key: value` lines is `true`; a body containing any blank line is `false`. The component passes `keepLineBreaks={segment.lineOriented}` and nothing else.

**5.1.7 `escapeStrayTags` and its schema guard.** Import `{ defaultSchema }` from `"rehype-sanitize"` (already in the client graph via `lib/markdown.ts`) and reuse the module-scope `safeTags` set from §5.1.2:

```ts
const safeTags = new Set(defaultSchema.tagNames ?? []);
```

`tagNames` is typed `Array<string> | null | undefined` (`hast-util-sanitize` `index.d.ts:222`), so calling `.includes` on it directly is a `tsc` error (`TS18049`); the `?? []` is part of the contract, not a style choice. Then scan line by line: skip fenced lines; reset inline-code state on a blank line; track backtick runs (a run of N opens, the next run of exactly N closes) and never touch anything inside a code span; at a `<` outside a code span, sticky-match `/<\/?([A-Za-z][A-Za-z0-9_-]*)((?:\s[^<>]*?)?)\s*\/?>/y` at that index and, when the name is not in `safeTags` and the preceding character is not `\`, insert `\` before the whole token. Autolinks (`<https://…>`, `<a@b>`) cannot match, `a < b` cannot match, `<b>`/`<br>`/`<code>`/`<kbd>`/`<details>` pass through untouched. No lookbehind anywhere.

**5.1.8 Why this is verified end-to-end, not by assumption.** The mitigation "a schema change fails loudly" is not a mitigation, so it is replaced by behaviour tests through the real `markdownRemarkPlugins` + `markdownRehypePlugins`: `escapeStrayTags` output for `"<tools>\nx"`, `"Pass -t <tools>,"` and `"a Vec<T>"` is rendered and must still contain the token as visible text (`&lt;tools&gt;`, `&lt;T&gt;`), never a dropped tag; `<b>bold</b>` must still render as an element.

**5.1.9 Prose safety is tested, not argued.** Four cases pin §5.1.2 through both the segmenter *and* the pipeline (tests (q1)-(q4) of TASK-001): a `<br>` line inside a body produces no section segment, leaves the later sections at their correct depths, and leaves no escaped `</project_context>` anywhere; a `<details>`/`<summary>` pair stays prose and renders as real HTML elements; `<div align="center">` stays prose and keeps its attribute; an `<img src="x.png" />` line stays prose and renders an `<img>` (never an `IMG` label).

The enclosing popover's own clamp is `calc(100dvh - ${topPanelPos.top}px)` with a **measured** top (§3.12), so the panel cannot guarantee that it fits without a scrollbar: when the popover is the shorter box the **outer** one scrolls, when the panel's own content is taller than its box the **inner** `.system-prompt-scroll` scrolls. Which of the two you see depends on the measured top, so the manual check (§8) states the honest expectation — **one scrollbar, outer or inner** — instead of claiming a single inner one in CSS. That is accepted and recorded in §7.

### 5.3 Locales

Four keys per locale, added right after `"system.label"` in the existing `system.*` group, no placeholders: `system.copy` (Copy / 复制 / 複製), `system.copied` (Copied / 已复制 / 已複製), `system.expand` (Expand / 展开 / 展開), `system.collapse` (Collapse / 收起 / 收合). **This lands before the panel** (§6): `translate` returns the key on a miss, so a half-finished wave would render a literal `system.copy` with nothing red.

**The duplication is deliberate** (answer to the auditor's fourth question): `i18n.copy`/`i18n.copied` (`en.ts:738-739`) and `i18n.collapse`/`i18n.expand` (`en.ts:1564-1565`) already carry the same four words, and they are **not** reused because the `i18n.*` namespace belongs to the settings › translation panel — borrowing it would couple two unrelated screens and make a future copy change in one silently reword the other. The four `system.*` keys keep the panel's strings greppable next to `system.prompt`/`system.empty`/`system.load`/`system.loading`/`system.label`, the panel is their only consumer, `lib/i18n/registry.test.mjs` keeps the three locales in lockstep, and the total cost of the duplication is four lines per locale.

### 5.4 Docs

No documentation task. The `docs/agents/tools.md` note and the `AGENTS.md` topic-index edit are dropped by decision; the module's traps live in its own comments and in its tests (§7 records the consequence).

### 5.5 Decisions taken in audit round 2 (the auditor's four questions, answered)

1. **Structural predicate (N1):** one predicate — lower-case name matching `^[a-z][a-z0-9_-]*$` **and** absent from `safeTags = new Set(defaultSchema.tagNames ?? [])` — evaluated at scan time, before frontmatter neutralisation and before escaping (§5.1.2). No balanced-lookahead, no wrapper allow-list.
2. **Lint gate (N3):** every lint gate is `npx eslint <that task's own files>` → exit 0, never `npm run lint`/`eslint .`, because repo-wide lint is red on this tree (`.next-old-*` is not ignored, §3.15); `eslint.config.mjs` and `.next-old-*` are explicitly out of scope (§4).
3. **Scope checks (N2):** per-task gates are `git status --porcelain=v1 -- <that task's exact paths>` plus "owns every path it added"; the whole-tree baseline delta is checked only by the post-wave tasks TASK-003/TASK-005, and TASK-000 asserts `test -s baseline.txt` plus an unchanged `git diff --stat` instead of an unobservable porcelain delta (§4, §8).
4. **Duplicated locale keys (N8):** the four `system.*` keys stay; reusing the settings panel's `i18n.*` namespace is rejected; the duplication is recorded as deliberate in §5.3.
